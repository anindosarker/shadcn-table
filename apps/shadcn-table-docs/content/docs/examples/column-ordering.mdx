Column ordering is on by default; this example states `enableColumnOrdering: true` to make that explicit. The header cell itself is the drag source: the cursor turns into a grab hand over it, a click still opens the column menu, and dragging a header onto another moves the column there; the new order lives in the `columnOrder` state, so you can read it, control it or save it like any other TanStack Table state. The column visibility menu in the view settings follows the same order.

Keep it on when users scan wide tables and want the columns they care about next to each other, for example moving a status column beside the name. Pair it with `persistViewSettings` (see the [Persistent View Example](/docs/examples/persistent-view)) when the order should survive a reload, or set `initialState.columnOrder` with `enableColumnOrdering: false` when you only need a different starting order and no dragging.

No grip renders by default; set `showColumnDragHandle: true` when you want a visible drag handle in each header cell. Learn more about column ordering in the [Column Ordering Feature Guide](/docs/guides/column-ordering-dnd).
