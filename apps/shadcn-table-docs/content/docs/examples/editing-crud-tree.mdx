Editing nested row data can be challenging. In this example, rows expand to show their sub-rows (`enableExpanding`), and editing and creating rows works at any level of the tree with `editDisplayMode: 'row'` and `createDisplayMode: 'row'`. Each row has an add button that opens a blank row directly under its parent: the `positionCreatingRow` option takes the row index where the new row should appear.

The example also shows client-side optimistic updates on nested data: after a valid save, the table data changes at once, and the TanStack Query mutation finds the right parent to insert the new row into. The actions column is pinned through `enableColumnPinning` and `initialState.columnPinning`, so the buttons stay in view for deeply indented rows.

Use this pattern for hierarchies users maintain by hand, such as an org chart, a category tree or a bill of materials. Check out the flat editing modes in the [editing guide](/docs/guides/editing) for more information.
