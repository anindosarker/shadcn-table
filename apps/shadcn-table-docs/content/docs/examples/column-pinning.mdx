date: '2026-11-10'
---

Column pinning is on by default and this example states `enableColumnPinning` explicitly: each column menu offers to pin the column to the start or the end of the table, and it starts with columns already pinned through `initialState.columnPinning`. Pinned columns stay in place while the rest of the table scrolls horizontally; the example also turns on `enableRowActions` with `renderRowActionMenuItems` so the actions column can stay pinned at the edge, and uses `layoutMode: 'grid-no-grow'` to keep column widths fixed.

Use column pinning for wide tables where one or two columns identify the row, such as a name or an ID, and users lose track of the row as they scroll right. Pinning the actions column to the end is a common second use: the edit and delete buttons stay reachable without scrolling back.

The `start` and `end` sides follow the reading direction, so the same setup works in right-to-left locales. See the [Column Pinning Feature Guide](/docs/guides/column-pinning) for more information.
