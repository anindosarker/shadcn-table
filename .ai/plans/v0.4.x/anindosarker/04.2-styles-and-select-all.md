# 04.2: styles and select all

## 1. Architecture

### 1.1 Overview

Two rulings from the owner's second review pass: the registry must not write to the
consumer's global stylesheet ([decisions-review.md](decisions-review.md) 16), and the header
checkbox under `select-*` pinning acts on the rows displayed on the page (17). The docs
installation page merged from `wt2` (`edbbb920`) describes install, update and uninstall and
is the place for the CSP note. Nothing is decided here.

### 1.2 Goals

- `packages/shadcn-table/registry.json` items carry no `css`; `registry/<base>/index.css`
  holds no ST rule; `scripts/registry/lib.mjs` has no CSS block parser
- `ST_LinearProgressBar` and `ST_GlobalFilterTextField` render a hoisted
  `<style href="st-..." precedence="low">` with their keyframes; one tag per name in `<head>`
  with two tables mounted; the indeterminate bar animates and the search field slides on
  both bases
- A fresh `shadcn add` of the main item leaves the consumer's `globals.css` untouched
  (verified on the docs app's `lib:install` output and on a scratch app)
- On page 2 of `select-all-page-mode`: mixed box, click gives 8 of 8, click gives 0 of 8 with
  no pin and label `6-8 of 8`; `select-all-all-mode` and plain pagination unchanged
- Docs: install page notes the hoisted style tag and the CSP requirement; uninstall section
  has nothing to say about CSS; `check-pages` green

### 1.6 Components

#### 1.6.1 Data artifacts

- `registry.json` (both items) loses `css`; `registry.ts` per base if it lists css; the
  hosted copies follow through `registry:hosted`
- `CHANGELOG.md` `## Unreleased`: Changed, the keyframes ship inside the components, no
  global CSS written on install; Fixed, select all on a page with kept pinned rows
- `install.mdx`: one short note under install (or verify) on the hoisted `<style>` and CSP;
  the uninstall section states that removing the files is the whole uninstall

#### 1.6.2 Hoisted styles (ruling 16)

- A module-level string per component with the exact CSS from `index.css`; rendered as
  `<style href="st-linear-progress" precedence="low">{css}</style>` (React 19 hoists and
  dedupes by `href`); the Base UI `ST_GlobalFilterTextField` keeps its four keyframes
- Does NOT use the Web Animations API or inline styles for the loop
- Does NOT change class names or the `data-slot` the rule targets

#### 1.6.3 Select all over displayed rows (ruling 17)

- `getST_DisplayedRows(table)` in `row.utils.ts`: page rows plus `getTopRows()` and
  `getBottomRows()` when `keepPinnedRows` and a `select-*` mode, deduped by id
- `getST_SelectAllHandler`: page mode with a `select-*` mode writes one `setRowSelection`
  updater over the displayed selectable rows; otherwise core's `toggleAllPageRowsSelected`;
  `selectAllMode: 'all'` unchanged; the ruling 9 clear stays
- `ST_SelectCheckbox` header: checked and indeterminate from the same helper
- Does NOT change row-level selection or Shift ranges
