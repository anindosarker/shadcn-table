### 1.6.2 Provider, atom reads, hook selector

- `ST_TableInstance` gains `AppTable: AppTableComponent<ST_Features>`; `ST_TableProvider` renders
  `table.AppTable`, which `useAppTable` attaches and which provides on the `tableContext`
  `createSTTableHook` passes in, so `useSTContext` reads it unchanged.
- No story asserted the handle, the `key` note or `useST_Atom`, so none was adjusted.
  `TableProvider.stories` gains `TableSwapWithoutKey`: one provider handed a second table with
  no `key`; the reader follows it and the subtree under the provider remounts.
- Atom reads are `useSelector(table.atoms.<slice>)` with the selector left out
  (`@tanstack/react-store` defaults it to identity): one atom subscription per call as before,
  36 calls in 12 files. Not `useSelector(table.store, selector)`, which would run every
  selector on every store change.
- `@tanstack/react-store` pinned at `0.11.2` (what `@tanstack/react-table` 9.3.1's `^0.11.2`
  resolves): `packages/shadcn-table/package.json`, the lockfile, both `registry.ts` dependency
  lists (pinned, so `registry.json` lists `@tanstack/react-store@0.11.2`), and the
  `existing` scenario pre-install in `.github/workflows/install.yml`.
- Not done here: `apps/shadcn-table-docs/package.json` has no `@tanstack/react-store`, and
  `lib:install` restores the docs `package.json` and lockfile after the CLI runs. Add it there
  before the final phase runs `lib:install` and the docs gates. The docs copies under
  `components/ui-radix` and `components/ui-base` are not refreshed in this phase.
- Ruling 13 needs a selected table to reach `ShadcnTable` and `ST_TableProvider`, which the
  task's "ShadcnTable.tsx unchanged" and "ST_TableProviderProps unchanged" do not allow for.
  Types only, root selector unchanged:
  - `ST_TableInstance<TData, TSelected = ST_TableState<TData>>`: the second parameter types
    `state`, as `ReactTable`'s does; the default keeps every existing use as it was.
  - `useShadcnTable` and `useST_TableInstance` are generic over `TSelected`; the selector is
    `(state: TableState<ST_Features>) => TSelected`, as `useAppTable`'s.
  - The inputs that never read `table.state` take `ST_TableInstance<TData, unknown>`:
    `ST_TableProviderProps.table`, the `table` prop of `ShadcnTable` (and its local), the
    `useST_Effects` parameter and `getCanRankRows`.
- The option-time transforms (display columns for grouping and the creating row, filter
  modes, skeleton rows) run on owner renders, so `useST_TableInstance` adds a second owner
  subscription after `useAppTable`: `useSelector(table.store, selectST_TransformState,
  { compare: shallow })` from `@tanstack/react-store`. A hook selector that leaves out the
  transform slices still gets them (review round 1); `TSelected` and `table.state` are
  unchanged. `RenderCounts.stories` `HookSelectorFollowsTransformState` selects only
  `pagination` and asserts the expand column after `setGrouping`; it fails without the
  subscription. `ShadcnTable` still passes `selectST_TransformState` as its root selector
  (ruling 15), so its owner subscribes twice to the same slices.

### 1.6.3 Instance types

- `ST_HeaderGroup` unchanged: core `HeaderGroup` has no `table`. `ST_Header` keeps its one type
  parameter.
- 27 casts removed, all under `components/`; none under `hooks/` or `shared/` was on an
  `instance.table` read.
- Casts kept, for another reason than an `instance.table` read:
  - `hooks/stTableHook.tsx` `useSTContext`: `useTableContext() as unknown as ST_TableInstance<TData>`,
    core context type to the ST wrapper type.
  - `hooks/useST_TableInstance.ts`: `useAppTable(...) as unknown as ST_TableInstance<TData, TSelected>`,
    re-types the getters.
  - `features/stEditingFeature.ts` (`createRow`), `features/stFilterModesFeature.ts` (`atoms`),
    `features/stRefsFeature.ts` (`refs`): feature code on the core table.
  - The plan 2.2 grep on `{components,hooks}` therefore lists the two `hooks/` casts; plan 1.2
    and 2.2 now say so (review round 1).
- The comment above `const table = <instance>.table` in 10 components per tree, which still
  explained the removed cast, is dropped (review round 1).
- `shared/utils/tanstack.helpers.ts` `createRow`: `as ST_Row<TData>` became
  `as unknown as ST_Row<TData>`; core `Row` and `ST_Row` no longer overlap once `table` narrows.
  Its existing `as any` arguments are unchanged.
- `row.table`, `cell.table`, `column.table` and `header.table` are the core table at runtime.
  Typed `ST_TableInstance<TData>`, they declare `state` and `AppTable`, which it does not
  have (ruling 7 as decided).
- No TS2589 or circularity; the type alias overlay stays.
