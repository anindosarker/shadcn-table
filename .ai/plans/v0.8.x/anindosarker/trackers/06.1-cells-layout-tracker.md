## Attention

- F24 root cause is outside this story's files: `hooks/useST_TableOptions.ts:219-222` (three bases) defaults `getRowCanExpand` to true for every row once `renderDetailPanel` is set, so on the detail-panel docs page (`enable-detail-panel-conditionally`) row 3, whose `renderDetailPanel` returns null, gets an enabled expand button and expands to an empty panel. Fix there: `getRowCanExpand ?? ((row) => renderDetailPanel ? !!renderDetailPanel({ row, table: row.table }) : (enableExpanding ?? true) && !!row.subRows?.length)`, so `ST_ExpandButton` disables that row as 0.7.4 did; then a play expanding every enabled row asserts each shows its panel. `PanelRenders` and `PanelRendersVirtualized` pass on the shipped code: the panel renders with height in the grid layout, with and without virtualization.
