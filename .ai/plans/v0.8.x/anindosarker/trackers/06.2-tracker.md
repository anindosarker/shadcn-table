## Attention

- Library: a `multi-select` filter matches nothing on a string column. `getDefaultColumnFilterFn` picks `arrIncludesSome` for it (`shared/utils/column.utils.ts:154`, three bases, registered at `shared/fns/filterFns.ts:207`), and table-core 9.3.1's `filterFn_arrIncludesSome` returns false unless the row value is an array (`@tanstack/table-core/dist/features/column-filtering/filterFns.js:299-305`). Seen on the home demo with `value: ['In Progress', 'In Review']` (no rows); the State multi-select of `customize-filter-variants` and `subheader-filters` is the same column shape. The home demo's Filtering step uses a `select` Status filter (`value: 'In Review'`) instead of the spec's list value; switch it back once the library fix lands.
- Library, from reading the code, not reproduced: the columns menu drag hands viewport `left` values to the column slide (`components/menus/ST_ShowHideColumnsMenuItems.tsx:83-91`), while the slide measures header lefts relative to the table (`hooks/useST_ColumnFlip.ts:42-55, 309-312`), so a reorder from the menu may slide every column by the table's page offset.
