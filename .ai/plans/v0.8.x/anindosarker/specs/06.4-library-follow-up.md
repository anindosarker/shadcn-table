# 06.4: Library follow-up

## 1. Architecture

### 1.1 Overview

The owner's second review of 0.8 on `claude/review` (2026-11-05) left six library items: the combined grouping header reads "State, Gender" behind one icon and keeps the 180 px default while the grouped columns leave the table (D68) (D73); the internal toolbar buttons fade in from 10 percent opacity, a test-driven deviation from the spec 04 animation (D70) (F40); the multi-select filter field has no chevron, an empty clear slot that takes room, no auto highlight, and its chip editor grows sideways with every pick (D72) (F55); the aria range slider renders both thumbs at 0 (F46); a column drag in an RTL table slides every header but the first off the table (F50). This sub-spec fixes them at the root in the three bases, each with a play that reproduces it on the shipped code first (P10). Two stories in sprint S10, one builder each, draft PR at the first push (P2), gates only: "Grouping header (06.4)" owns the expand column def, the head cell's icon rendering and the column utils; "Filters, toolbar, RTL (06.4)" owns the filter field, the aria range slider, the header filter editor, the internal buttons group and the column flip hook. D72's accepted diff is applied as is, in place, no new helper (P12).

### 1.2 Goals

- Under `groupedColumnMode: 'remove'` the grouping column's header is the expand-all button (when `enableExpandAll`) followed by one segment per grouped column in grouping order, each the column's icon and header name, segments separated by a right chevron; under `'reorder'` the expand column keeps its empty header (D68)
- Under `'remove'` the grouping column's default `size` is the sum of the grouped columns' sizes, recomputed as grouping changes; `displayColumnDefOptions['st-row-expand'].size` wins; the breadcrumb never truncates (D73)
- Every internal toolbar button mounts with `animate-in fade-in zoom-in-75 duration-200 motion-reduce:animate-none`, from 0 opacity, as `ST_ViewSettingsItems` does (D70)
- The multi-select filter field shows a `ComboboxTrigger` chevron at its end, vertically centred, the clear X only once a value exists (no empty slot), the chips and the input wrapping inside the field, and on radix and base `autoHighlight` so typing highlights the first match and Enter picks it; the chip editor popover is `w-65` so chips wrap instead of widening it (D72) (F55)
- The aria `range-slider` filter reads `min`/`max` from `stFilterSliderProps` as radix and base do, so the shared examples place the thumbs at the ends (F46)
- A column drag preview in an RTL table lays the slots right to left: every header stays inside the table and only the dragged and target columns shift (F50)
- Acceptance: programmatic, the plays of 1.6.8 pass in `test:base`, `test:radix` and `test:aria`, each play run on the shipped code first and failing there (the failing run noted in the tracker), and `check:bases` green
