# 06.2: docs and stories follow-up

## 1. Architecture

### 1.1 Overview

The owner's review of the 0.8 docs site (2026-11-04) found the home demo and the filtering examples still on the 0.7 chrome, plain headers where the demo shows icons, a docs stylesheet rule clipping every pagination, and a handful of example defects (D45) (D46) (D49) (D50) (D51) (F10) (F13) (F14) (F15) (F21) (F26) (F27). This sub-spec reworks the docs app and the stories to the shipped 0.8 look. Two stories: "Docs app (06.2)" owns `apps/shadcn-table-docs/` (sprint S6, beside the library fix stories); "Stories and DefaultLook (06.2)" owns `packages/shadcn-table/stories/` (sprint S7, after the library fixes merged, because those stories edit play tests). One builder each, draft PR at the first push (P2), one fable review on the docs app story (`Review: fable`).

### 1.2 Goals

- Every column definition in the docs examples (116 per base) and in every story file (76) carries `icon`, a Lucide `*Icon` component; columns built in a loop (`enable-column-virtualization`, `dynamic-columns`, `Virtualization.stories.tsx`, `RowOrdering.stories.tsx`) take one icon from a lookup by key (D45) (D49)
- The home demo renders the stock table over the persistent-view data with the stock defaults and six scripted steps for the 0.8 chrome (D46)
- The persistent-view example renders the DefaultLook data and columns, 50 rows, 15 columns (D50) (F13)
- The four filtering examples run in chips mode; one new page, Subheader Filters Example, keeps the subheader system (D51) (F26)
- Every example page shows the view settings button except `minimal`; the pagination is never clipped; the row ordering and row dragging copy say row; no data column `size` below 56; the chart detail panel draws its lines; the editing examples put the actions column first (D52) (F14) (F15) (F21) (F22) (F25) (F27)
- The DefaultLook story renders `ShadcnTable` with columns, data, `getRowId` and `enableRowActions` only (F10)
- Acceptance: programmatic. Docs app story: `node scripts/check-pages.mjs --base <base> --url http://localhost:<port>` exits 0 per base against the builder's own dev server, with the clusters rewritten for chips; docs `types:check`, `lint`, `build` exit 0; `node reference/06.2-check.mjs` (committed by this story) exits 0: for every `examples/<base>/*/TS.tsx` and `makeData.ts` and `components/UsersTable.tsx`, every `accessorKey:` or `columnHelper.accessor(` has an `icon:` in the same column object, the three exceptions excepted; `signal-table.tsx` contains no `columnFilterDisplayMode`; `global.css` has no `:is(p, ul, ol)` rule reaching `.not-prose`.
