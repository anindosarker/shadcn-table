# 06.6: Edition icons

Follow the project planning rules: docs/code-of-conduct/planning-guidelines.md, CLAUDE.md:9. Keep the expedition contract.

## 1. Architecture

### 1.1 Overview

The Tabler, Phosphor, Remix and Hugeicons editions (`icons/tabler.ts`, `icons/phosphor.ts`, `icons/remixicon.ts`, `icons/hugeicons.ts`, three bases) still import the drawn grid line glyphs from `components/icons/ST_GridLineIcons.tsx` and map their own rows icons for density and columns, so an edition install shows other view settings icons than the Lucide default (F59). This sub-spec maps the eight D75 keys per edition to the picks of D77, deletes the drawn glyph file in the three bases with its `index.ts` export, registry entries and docs copies (D76), and makes `check:icons` refuse any map that imports from `components/icons/`.

### 1.2 Goals

- Every edition map shows the D77 icon for each of the eight D75 keys (`GridLinesAllIcon`, `GridLinesRowsIcon`, `GridLinesColumnsIcon`, `GridLinesNoneIcon`, `ViewColumnIcon`, `DensitySmallIcon`, `DensityMediumIcon`, `DensityLargeIcon`), rotation and mirroring through a wrapper that adds `rotate-90` or `-scale-x-100` as D75's `EqualVertical` and `ListIndentDecreaseFlipped` do.
- `components/icons/ST_GridLineIcons.tsx` is gone from the three bases, from `index.ts`, from `registry.json` and `public/r/` (D76).
- Acceptance: programmatic, `pnpm check:icons` green per base with the new rule (no map imports from `components/icons/`), the rule failing on the shipped code first (noted in the tracker); the play `EditionIconsRender` of 1.6.4 passes in `test:base`, `test:radix` and `test:aria` and fails on the shipped code (P10); `pnpm -w registry:build` green with `grep -r ST_GridLineIcons packages/shadcn-table/registry packages/shadcn-table/registry.json packages/shadcn-table/public/r` empty; `check:bases` green.

#### 1.6.2 Edition maps (D77)

- Each map keeps one `Key: Glyph,` line per key in the `ST_Default_Icons` literal (`check:icons` reads `^\s+(\w+):` lines), the picks of D77 replacing the current entries in place (P12), the import lists sorted as today, the glyph import removed.
- Rotated and mirrored entries: a `const` wrapper above the map, named after the icon (`IconEqualVertical`, `EqualsVertical`, `TextOutdentFlipped`, `RiEqualVertical`, `RiIndentDecreaseFlipped`, `EqualVertical`, `ListIndentDecreaseFlipped`), built with `createElement` and `cn('rotate-90', props.className)` or `cn('-scale-x-100', props.className)` as `icons.ts:60-70` does; Remix and Hugeicons wrappers go through the map's `icon()` helper first (`icon(RiEqualLine)` then the className) so the children and stroke handling stay.
- `cn` from `@/lib/utils` (already imported by `icons.ts`); props type `ST_IconProps` from `@/components/ui/shadcn-table/types` (Remix and Hugeicons import it already; Tabler and Phosphor add it).
- Does NOT change any other key, any `icons.ts` line, or `types.ts`.

#### 1.6.3 Glyph file deletion (D76)

- `git rm` `components/icons/ST_GridLineIcons.tsx` in the three bases; delete line 88 of `index.ts` in the three bases (`export * from '@/components/ui/shadcn-table/components/icons/ST_GridLineIcons';`); `pnpm -w registry:build` rewrites `registry.json` and `public/r/`.
- `scripts/check-icons.mjs`: after the key parity, a second check per map: the source contains no `components/icons/` import; a hit prints `<map>: imports from components/icons/` and counts as a problem.
- Does NOT touch `scripts/registry/bases.mjs`, `lib.mjs` or `build.mjs`.

#### 1.6.4 Plays (P10)

- `EditionIconsRender` in `ViewSettings.stories.tsx`: a story that renders the eight D75 keys of each of the four edition maps (import the four maps from `@/components/ui/shadcn-table/icons/<set>`) in a grid, one `data-testid="<set>-<key>"` wrapper per icon; the play asserts an `svg` inside each of the 32 wrappers, and that the `svg` of `<set>-GridLinesColumnsIcon` carries the class `rotate-90` and the `svg` of `<set>-DensityMediumIcon` carries `-scale-x-100` for Phosphor, Remix and Hugeicons (Tabler keeps `IconBaselineDensityMedium` unmirrored, D77). On the shipped code the `rotate-90` assertion fails for all four sets (the drawn glyph has no rotation class).
