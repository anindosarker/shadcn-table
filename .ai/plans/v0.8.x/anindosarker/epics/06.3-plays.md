# 06.3: plays for every story file

## 1. Architecture

### 1.1 Overview

On `claude/review` the 79 story files hold 542 stories and 101 plays; 47 files have none, among them the features 0.8 changed most (ColumnResizing, ColumnOrdering, ColumnPinning, Editing, Pagination, Toolbar, Search, RowPinning, LayoutMode, DefaultLook, StickyHeader), so `test:<base>` proves only that those stories mount (D59) (P10). This sub-spec gives every story file at least one play and every feature file one play per behaviour it demonstrates, in the three bases. One story "Plays (06.3)", sprint S9, after the last fix story (which adds plays to some of the same files), one builder, draft PR at the first push (P1), gates only.

### 1.2 Goals

- No story file without a play; every `features/*.stories.tsx` has one play per behaviour the file's stories show (the list in 1.6.2), each play asserting the behaviour's visible result, not only that an element exists
- Plays fail when the behaviour is broken: each new play is run once against a deliberate break of the behaviour (a local, uncommitted edit, reverted after) for one sample play per file, noted in the tracker
- `test:base`, `test:radix`, `test:aria` green with the new plays; the builder records each base's `test:<base>` wall time at the start commit, before the first play, in the tracker, and the final runtime per base stays under twice that
- Acceptance: programmatic, `node reference/06.3-check.mjs` (committed by this story) exits 0: every `*.stories.tsx` under `packages/shadcn-table/stories/` contains at least one play (`play:` or `Story.play =`); every file under `stories/features/` contains at least the play names 1.6.2 lists for it; and `test:base`, `test:radix`, `test:aria` green one base after another

### 1.6 Components

#### 1.6.1 Data artifacts

#### 1.6.2 Plays per feature file

Each play uses the file's existing stories (or one new story where none fits), the shared `stBrowserUserEvent` helper for real pointer work, and `within(canvasElement)` queries by role and name. Required play names per file:

| File | Plays |
|---|---|
| ColumnResizing | `DragResizesColumn` (handle drag widens the column, header and body cell widths equal within 1 px), `DoubleClickResetsWidth`, `ResizeMenuItemResets` (D5 addendum) |
| ColumnOrdering | `MenuReorderMovesColumn` (columns menu drag, header order changes, body follows), `LockedColumnStaysPut` |
| ColumnPinning | `PinStartSticks` (pinned cell `position: sticky`, offset 0), `UnpinRestores`, `PinnedEdgeShadow` (D22 shadow class present) |
| Editing | `CellEditSaves` (cell mode: type, blur, value shown), `RowEditSaveCancel` (row mode: cancel restores), `ModalEditSaves` |
| Pagination | `NextPageChangesRows`, `PageSizeChangesCount`, `PagesModeNumbers` (D13 numbers visible, last page reachable) |
| Toolbar | `InternalButtonsOrder` (D8 order by aria-label), `CustomActionsRender`, `BottomToolbarAlertBanner` |
| Search | `TypingFiltersRows`, `ToggleClearsAndCloses` (D35), `EscapeClearsThenCloses` |
| RowPinning | `PinRowTopMode` (`rowPinningDisplayMode: 'top'`: the pinned row is the first body row), `PinRowSticky` (default mode: same index, `position: sticky`), `UnpinRow` |
| LayoutMode | `GridGrowsColumns` (data columns grow, display columns do not, D31), `SemanticLayoutRenders` |
| DensePadding | `ToggleChangesRowHeight` (three densities, three heights) |
| Aggregation | `GroupedRowShowsAggregate` (the aggregated cell value matches the group) |
| ColumnGrouping | `GroupByBanner` (banner lists the group chip), `ExpandGroupShowsRows`, `GroupedHeaderHasIcon` (F41) |
| Virtualization | `ScrollRendersFurtherRows` (row count rendered less than data, further rows appear on scroll), `ColumnVirtualizationScrollsHeaders` |
| SubRowTree | `ExpandShowsChildren`, `ExpandAllCollapseAll` |
| Creating | `CreateRowAppears` (a story whose `onCreatingRowSave` appends to its data: new row in edit, save adds it) |
| FullScreen | `ToggleFullScreen` (root gets the full screen attribute, Escape leaves) |
| CellActions | `RightClickOpensMenu`, `MenuItemRuns` |
| ClickToCopy | `ClickCopiesValue` (clipboard write called with the cell text, tooltip shown) |
| Loading | `SkeletonsWhileLoading`, `ProgressBarShown` |
| RowOrdering | `DragReordersRows` (grip drag, order changes), `DropSlidesRows` (D57, `getAnimations()` on the moved row right after drop) |
| RowDragging | `DragBetweenTables` (a new two-table story mirroring the docs row-dragging example: the row leaves the source table and appears in the target) |

Files that already have plays keep them; a behaviour above missing from one of those files is added there too (for example `ColumnDragging` has drag plays, none for the D37 highlight: add `DropHighlightsColumn`).

- Does NOT change library source, the test runner config, or story args beyond what a play needs; a play that needs a behaviour the library lacks is a tracker Attention line with file:line, never a skipped assertion

#### 1.6.3 Styling and fixed-bugs files

One play per file asserting the file's point: a styling file asserts the computed style its stories set (a class present, a colour or height value); a fixed-bugs file asserts the bug's absence as its name says (for example `click-propogation`: a cell click does not trigger the row click; `sticky-footer`: the footer is `position: sticky`; `PaginationDisabled`: no pagination rendered; `useEffects`: the effect ran once per change). `Basic.stories.tsx` gets `RendersRows`.

#### 1.6.4 Check script

`reference/06.3-check.mjs`: walks `packages/shadcn-table/stories/`, reports every `*.stories.tsx` without a play (`play:` in a story object or a `Story.play =` assignment, nine files already used the assignment form), and for each `features/` file the names of 1.6.2 not found as a `play` on a story with that export name; exit 1 on any report.
