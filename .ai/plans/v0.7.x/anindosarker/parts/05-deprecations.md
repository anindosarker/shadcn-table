# 05: deprecations

## 1. Architecture

### 1.1 Overview

The library uses five deprecated APIs that strike through in a consumer editor: the `aggregationFns`, `filterFns` and `sortFns` registries, `table.store` and `navigator.platform` (F8). The registries are rebuilt from the individual `*Fn_*` exports, one helper owns the platform read (D11), and every `table.store` use becomes `table.Subscribe`, `table.atoms.<slice>.get()` or a per-atom subscription (D13). The `table.store` migration also covers the stories, the hand-written docs examples and one guide line (D13 amended). Runs in stream S1 (index, Run plan) (D34): the `ST_TableAtoms` and `ST_DisplayColumnOptions` types (1.6.5, 1.6.6) land in the foundation; the registries and the platform helper (1.6.2, 1.6.3) are the S1 lead step, after the 02 config switch (`no-deprecated` active) and the 03 atoms (the `useSelector(table.store)` site in `useST_TableInstance.ts` is gone); the `table.store` rewrites (1.6.4 to 1.6.8) are applied per file set A to D; the long gates run once at stream end.

#### 1.6.4 `table.Subscribe`

`ST_TableInstance` is `Omit<ReactTable<ST_Features, TData, TSelected>, …>` with `Subscribe` not omitted, so it carries the overloads of `ReactTable['Subscribe']` (`@tanstack/react-table` 9.3.1 `dist/useTable.d.ts:50-62`); `ST_CoreTableInstance` keeps it. The store overload omits `source` and types `selector` as `(state: TableState<ST_Features>) => TSubSelected`; the runtime fills `source` with `tableInstance.store` (`dist/useTable.js:46-51`, `source: props.source ?? tableInstance.store` at :49), and `Subscribe` compares with `shallow`. Rows, cells and columns reference the same instance.

Rule: every `<Subscribe source={table.store} selector={s}>` becomes `<table.Subscribe selector={s}>`, selector text unchanged. The standalone `Subscribe` import goes from a file only when no `source={table.atoms.<slice>}` site remains there.

| Operation | Status | Notes |
| --- | --- | --- |
| 30 `<Subscribe source={table.store}>` sites (F8 list) | refactor | `<table.Subscribe>`, selector text unchanged |
| standalone `Subscribe` import | refactor | removed where no `source={table.atoms.<slice>}` site remains |

```tsx
// before
<Subscribe selector={(state) => ({ grouping: state.grouping })} source={table.store}>
  {({ grouping }) => …}
</Subscribe>
// after
<table.Subscribe selector={(state) => ({ grouping: state.grouping })}>
  {({ grouping }) => …}
</table.Subscribe>
```

**Stays unchanged:** the 14 `Subscribe source={table.atoms.<slice>}` sites, `useSelector(table.atoms.<slice>)` calls.

#### 1.6.5 Snapshot reads

Rule: each `table.store.state.<slice>` read in a handler, effect or util becomes `table.atoms.<slice>.get()` per slice read. `table.state` is not used: it is the owner's selector value and not reactive.

`ST_TableInstance` omits `atoms` and re-declares it typed per row type, mirroring table-core `Atoms<TFeatures>` (the type lands in the foundation); the `as ST_TableState<TData>` casts at `row.utils.ts:31`, `ST_ShowHideColumnsMenu.tsx:168` and `useST_Effects.ts:74` go.
