## Attention

- React Aria 1.22.1's standalone `Tooltip` reads its state from `TooltipTriggerStateContext` in its inner component even when `isOpen` is passed (it throws "Cannot read properties of null (reading 'isOpen')" without a trigger), so aria `ST_Tooltip` standalone mode wraps the part's `Tooltip` in `TooltipTriggerStateContext.Provider` with a state object built from `isOpen` (both exported by react-aria-components; `react-stately` is not a dependency). Upstream not filed.
- The grouped value's bubble text is the grouping column's header ("State"), as in base `getST_RowExpandColumnDef.tsx`, not the grouped value the task text named.
- The aria `RadioGroup` in single-selection mode gets `className="w-fit"`: without the removed `inline-flex` span its `w-full` would stretch over the cell and center the bubble on the cell instead of the radio.
- The grouping value's tooltip lives in a small `ST_GroupingValue` component in `getST_RowExpandColumnDef.tsx`: `Cell` runs as a plain function and cannot hold the open state.
- The filter tooltip opens from the checkbox only (events on the control, spec 1.6.3); base opens it from the whole label including its text.
- In the aria captures the checkboxes sit about 5 px lower than in base (all rows and the header); not checked whether this predates the spec.
- The aria standalone checkbox bubble opens on focus only when the control matches `:focus-visible` (react-aria `isFocusVisible` is not importable: only `react-aria-components` is a dependency). Hover behaviour after a press was not rechecked in a browser.
