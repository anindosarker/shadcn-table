## 1. Architecture

### 1.1 Overview

Spec 10.1 removed the tooltip wrappers from the aria `ST_SelectCheckbox`, `ST_FilterCheckbox` and the row-expand grouping value, because React Aria's `Focusable` warns about a child that cannot take focus, and left the text as `aria-label` or `title` (A34). Base and radix still show the bubble on hover. D61 brings it back in the aria base with React Aria's documented standalone `Tooltip` (`triggerRef` plus `isOpen`), no `Focusable`, no `TooltipTrigger`, no warning. Sub-spec of 10; workstream T7 (index, Run plan): branch `v0.7/aria-standalone-tooltip`, worktree `../shadcn-react-table.worktrees/aria-standalone-tooltip`, from `claude/review`. #### 1.6.2 `ST_Tooltip` standalone mode, aria

React Aria's `Tooltip` works without a `TooltipTrigger` when it gets `triggerRef` and `isOpen` ("`triggerRef` ... only required when used standalone"). The component already holds the child's node in `triggerRef` (`:60`, merged with the child's own ref through `useST_ComposedRef`).

- Does: a `standalone?: boolean` prop. When set, the component renders the child cloned with `attachRef` and, as a sibling, the part's `Tooltip` with `triggerRef={triggerRef}`, `isOpen={isOpen}`, `onOpenChange` as today (Escape and blur dismiss until `open` changes, `:72-82`), `placement={commonSide}`, no `TooltipTrigger`, no `Focusable`; `open` is required in this mode and the JSDoc says so (`open` undefined renders the child alone)
- Does: the `disableHoverListener` and empty-title early return (`:84-86`) and the `applyTooltipLabel` effect (`:61`) apply in both modes; the disabled-child return (`:90-92`) applies to the trigger mode only (a standalone tooltip has no `Focusable` to warn)
- Does: `delayDuration` and `disableHoverableContent` have no effect in standalone mode (the caller's open state is the timing); said in the prop JSDoc
- Does NOT change the trigger mode, the exported prop names, the part `tooltip.tsx`, or base and radix `ST_Tooltip.tsx`

**Operations:**

| Operation | Status | Notes |
| --- | --- | --- |
| `standalone` prop | new | aria `ST_TooltipProps` only |
| standalone render branch | new | child cloned with `attachRef`, part `Tooltip` sibling with `triggerRef`, `isOpen`, `onOpenChange`, `placement` |

**Interfaces:**

```typescript
export interface ST_TooltipProps {
  title?: React.ReactNode;
  children: React.ReactElement;
  side?: React.ComponentProps<typeof Tooltip>['placement'];
  delayDuration?: number;
  disableHoverableContent?: boolean;
  disableHoverListener?: boolean;
  open?: boolean;
  /**
   * Render the child as is and the tooltip beside it, positioned by the
   * child's ref and shown by `open`; for a child that cannot take focus.
   * `open` is required; `delayDuration` and `disableHoverableContent` do
   * not apply.
   */
  standalone?: boolean;
}
```

#### 1.6.3 The three sites, aria

Each site holds one `useState<boolean>` for the tooltip and drives it from the control's own events; the tooltip element is the existing wrapper the site already renders, so no element is added (D61).

- Does: `ST_SelectCheckbox`: `<ST_Tooltip standalone open={tooltipOpen} title={checkboxTitle ?? (selectAll ? localization.toggleSelectAll : localization.toggleSelectRow)}>` around the existing `<span className="inline-flex">` (`:166`); `onHoverStart`, `onHoverEnd`, `onFocus`, `onBlur` on the `ST_Checkbox` and on the `RadioGroupItem` (both `CheckboxProps` and `RadioProps` extend `HoverEvents` and `FocusEvents`) set the state, composed with a consumer's handlers from `checkboxProps`; the state lives in the component body, above `table.Subscribe` (hooks never inside the render prop); the `aria-label` stays (`:106-110`)
- Does: `ST_FilterCheckbox`: `<ST_Tooltip standalone open={tooltipOpen} title={checkboxProps.title ?? filterLabel}>` around the `Label` (`:80`), same four events on the `ST_Checkbox`; the label text stays
- Does: `getST_RowExpandColumnDef`: the grouping value span (`:39-43`) becomes a file-local component (`ST_GroupingValue`, not exported) that holds the state and renders `<ST_Tooltip standalone side="right" open={open} title={header}><span onPointerEnter onPointerLeave>{groupingValue}</span></ST_Tooltip>`; the `title` attribute goes (the bubble replaces it, as in base)
- Does: `stories/fixed-bugs/AriaTooltips.stories.tsx` (new, runs in every base): three stories, selection enabled, filter checkbox variant on a boolean column, grouping with `groupedColumnMode: 'remove'`; play tests per 1.2: hover shows `[role="tooltip"]` with the exact localization text, unhover hides it, Tab from the previous focusable lands on the checkbox input (no extra stop), `check:aria-warnings` story list gets the three new story ids
- Does NOT change base or radix, `types.ts`, `index.ts`, localization keys, `ST_Checkbox`, the `RadioGroup` or any part file; does NOT add `Focusable`, `TooltipTrigger`, `tabIndex` or a wrapper element at any site
