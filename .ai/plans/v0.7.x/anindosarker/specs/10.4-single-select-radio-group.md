# 10.4: single select radio group

## 1. Architecture

### 1.1 Overview

Single-row selection renders one `RadioGroup` per row with one item (`ST_SelectCheckbox.tsx` base :188-192, radix :186-190, aria :209-216), so arrow keys cannot move between rows and screen readers announce "1 of 1" (F45). D65: one group per table, one item per row. D66 rides along: the loading state gets a localization key, read by the progress bars. Sub-spec of 10; workstream T11 (index, Run plan): branch `v0.7/single-select-radio-group`, pool worktree `../shadcn-react-table.worktrees/01` (P1), from `claude/review` at 31cbd6d5. All three bases; `ST_SelectCheckbox.tsx`, `ST_LinearProgressBar.tsx` and (aria) `types.ts` are diff-listed, the rest byte-identical.

### 1.2 Goals

- With `enableMultiRowSelection: false`, the table has one `role="radiogroup"` and one `role="radio"` per row; ArrowDown and ArrowUp move the check between rows and `rowSelection` follows; a click still selects (D65)
- Screen readers announce the radio as "n of m" (one group); the group carries `aria-label={localization.toggleSelectRow}`; no new Tab stop beyond the one radio
- `ST_Localization.loading` exists with default `'Loading'`; every progress bar has `aria-label={localization.loading}` in every base (D66)
- Acceptance: the new play tests on `features-selection-examples--single-selection-radio` and `--single-selection-radio-with-row-click` pass in `test:base`, `test:radix`, `test:aria`: exactly one `[role=radiogroup]`, `rows.length` radios, click row 2 then ArrowDown checks row 3 and `table.getState().rowSelection` equals `{ [row3.id]: true }`; `check:aria-warnings` prints 0; a story with `isLoading` has a `[role=progressbar][aria-label="Loading"]` in all three bases (P6)

#### 1.6.2 The group in `ST_Table`

- Does: `ST_Table` reads `enableRowSelection` and `enableMultiRowSelection` from the table options; when row selection is on and `enableMultiRowSelection === false`, the `<table>` element renders inside the part's `RadioGroup` (a `div`; valid around a table, and the only placement that works in all three bases because the aria part has no render prop and a div cannot sit inside `<tbody>`); `value` is the selected row id from `table.getState().rowSelection` (the first key with `true`, else `null`); the change handler (`onValueChange` base and radix, `onChange` aria) calls `table.getRow(id).toggleSelected(true)` (TanStack clears the other rows in single-select mode); `aria-label={localization.toggleSelectRow}`; `className` resets the part's `grid w-full gap-2` to `contents` or `block` so the group adds no box; `tabIndex` untouched
- Does NOT change `ST_TableBody`, the pinned-row tbodies, `tableProps`, or render the group when multi-row selection is on
