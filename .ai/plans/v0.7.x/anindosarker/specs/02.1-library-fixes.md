# 02.1: library fixes

## 1. Architecture

### 1.1 Overview

Three small library and story defects left open after 0.7.1. The loading skeleton width is drawn with `Math.random()` in the `useState` initializer of `ST_TableBodyCell`, so a table that renders placeholders on the server hydrates with a React warning (F63) (D50). `getPlatform` falls back to the deprecated `navigator.platform` behind a `no-deprecated` disable that a consumer lint without that rule reports as unused (A38, D59). The column dragging story sets `enableColumnDragging` alone, so the drag starts and never reorders (F64) (D60). Sub-spec of 02; workstream T5 (index, Run plan): branch `v0.7/library-fixes`, worktree `../shadcn-react-table.worktrees/library-fixes`, from `claude/review`. All three bases; the two library files are byte-identical across bases (`check:bases`).

### 1.2 Goals

- A table that starts with `isLoading` renders the same skeleton widths on the server and the client: no `Math.random()`, no effect, no setState during render (D50) (D8)
- `getPlatform` reads `navigator.userAgentData.platform`, then a `navigator.userAgent` match; no `eslint-disable` for `no-deprecated` remains in the library, so a consumer lint with `reportUnusedDisableDirectives` reports zero problems (D59) (D17)
- The Storybook column dragging story reorders columns by dragging; the Column Ordering/DnD guide says in one sentence that dragging needs ordering or grouping as its target (D60)
- Acceptance: programmatic. `grep -rn "Math.random\|no-deprecated\|navigator.platform" packages/shadcn-table/registry/*/components/ui/shadcn-table/components/body/ST_TableBodyCell.tsx packages/shadcn-table/registry/*/components/ui/shadcn-table/shared/utils/utils.ts` prints nothing; `pnpm --filter shadcn-table test:base`, `test:radix`, `test:aria` green with the 1.6.4 play tests (deterministic widths across two mounts; the dragging story reorders); `pnpm check:bases` green (P6)

#### 1.6.2 Deterministic skeleton width

`ST_TableBodyCell`, all three bases. The width is a pure function of what both the server and the client know at first render.

- Does: replaces the `useState` initializer with a value computed during render from `column.getSize()`, `staticRowIndex` and the column's position in the row (`staticColumnIndex`, or the column id when the index is undefined), in the range the random draw used (`size / 3` to `size`), varying across rows and columns so the placeholders still read as text of mixed length; a display column (`columnDefType === 'display'`) stays `size / 2`
- Does: keeps the value stable for a given cell across renders (same inputs, same width); a column resize changes it with `column.getSize()`, as a mount-time draw would not, which is accepted
- Does NOT add an effect, a `mounted` flag, `useSyncExternalStore`, a `setState`, or a `Math.random()` anywhere in render (D8) (D50); does NOT change the `Skeleton` element, `stSkeletonProps`, `showSkeletons` or the isLoading branch at `:319-326`

#### 1.6.3 Platform helper

`getPlatform`, `shared/utils/utils.ts`, all three bases.

- Does: `navigator.userAgentData.platform` first; the fallback is a `navigator.userAgent` match that returns a lower-cased string containing `win` on Windows and `mac` on macOS (the two tests `cell.utils.ts:19-20` make: `platform.includes('win')`, `platform.includes('mac')`), `linux`, `android`, `iphone` or `ipad` where the agent says so, else the lower-cased `userAgent` itself; never throws
- Does: removes the `eslint-disable-next-line @typescript-eslint/no-deprecated` line and the `NavigatorWithUAData` comment stays accurate (D59 amends D11: the fallback is `userAgent`, not `platform`)
- Does NOT change the export name, the return type `string`, or `cell.utils.ts`

**Operations:**

| Operation | Status | Notes |
| --- | --- | --- |
| `getPlatform` (`:28-35`) | refactor | `userAgentData.platform ?? <userAgent match>`; no directive |
