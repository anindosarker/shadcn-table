# 02.1: library fixes

## 1. Architecture

### 1.1 Overview

Three small library-side defects left after 0.7.1: the loading placeholder width is drawn with `Math.random()` in a `useState` initializer, so server and client HTML differ and React logs a hydration warning (F63, D50); `getPlatform` falls back to the deprecated `navigator.platform` under a `no-deprecated` disable that a consumer lint reports as unused (A38, D59); the column dragging story has no drop target, so the handle drags and nothing reorders (F64, D60). Sub-spec of 02; workstream T5 (index, Run plan): branch `v0.7/library-fixes`, worktree `../shadcn-react-table.worktrees/library-fixes`, from `claude/review`. All three bases for the two library files; the story and the docs guide once.

### 1.2 Goals

- A table rendered on the server with `isLoading` hydrates without a React warning; placeholder widths still vary per row and column (D50) (D8)
- No `eslint-disable` for `@typescript-eslint/no-deprecated` in the library; `getPlatform` returns the same values as today on Chromium, Firefox and Safari (D59) (D17)
- The Column Dragging story reorders columns on drop, as the Column Ordering story does; the guide says what dragging needs (D60)
- Acceptance: `grep -rn "Math.random\|no-deprecated" packages/shadcn-table/registry/*/components/ui/shadcn-table` prints nothing; `check:bases` green; a Next 16 throwaway app page that renders `ShadcnTable` with `isLoading` logs no hydration warning in `next dev` (agent-browser console check, the app made the way spec 09.1 1.6.2 makes `gate-base`); the `ColumnDraggingEnabled` play test reorders (P6)
