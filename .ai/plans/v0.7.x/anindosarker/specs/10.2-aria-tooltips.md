# 10.2: aria tooltips

## 1. Architecture

### 1.1 Overview

Spec 10.1 removed the tooltip from the aria row and header select checkbox, the filter checkbox and the row-expand grouping value, because the aria tooltip part wraps its trigger in React Aria's `Focusable`, which warns on a child that is not a focusable element with an interactive role (A34). D61 restores the bubble through React Aria's documented standalone `Tooltip`: `triggerRef` plus `isOpen`, no `TooltipTrigger`, no `Focusable`, opened by the control's own hover and focus events. Sub-spec of 10; workstream T7 (index, Run plan): branch `v0.7/aria-tooltips`, pool worktree `../shadcn-react-table.worktrees/03` (P1), from `claude/review`. Aria tree only; base and radix keep their `render` and `asChild` triggers.

### 1.2 Goals

- In aria, hovering or focusing the row select checkbox, the header select-all checkbox, a column filter checkbox or a grouped-row value shows the same bubble with the same text as base and radix (D61)
- Zero React Aria development warnings stay zero (`check:aria-warnings`) (D44); no new Tab stop (`MenuOpeners` and the selection play tests unchanged)
- Acceptance: `check:aria-warnings` prints 0; the new play test in `fixed-bugs/AriaTooltips.stories.tsx` (aria run only) hovers each of the three controls and finds a `[data-slot=tooltip-content]` with the expected text, then blurs and finds none; judged: a capture per control in aria beside the same capture in base, three judges on "same bubble, same text, same placement" (P6)

#### 1.6.2 ST_Tooltip standalone mode (aria)

- Does: a `standalone?: boolean` prop; when set, `ST_Tooltip` renders `React.cloneElement(trigger, { ref: attachRef })` followed by `<Tooltip triggerRef={triggerRef} isOpen={isOpen} placement={commonSide}>{title}</Tooltip>` (the part's `Tooltip`, which spreads these onto React Aria's `Tooltip`; `triggerRef` is documented as the standalone way); the `open` prop and its dismissal state apply as in the trigger mode; `applyTooltipLabel` still writes the `aria-label`
- Does NOT change the trigger mode, the part files, or the `ST_TooltipProps` names already exported

**Interfaces:**

```typescript
export interface ST_TooltipProps {
  // existing members unchanged
  /** Aria only: no TooltipTrigger; the bubble positions on the child and opens from `open`. */
  standalone?: boolean;
}
```

#### 1.6.3 Call sites

- `ST_SelectCheckbox`: a local `open` state per cell from the control's `onHoverStart`, `onHoverEnd`, `onFocus`, `onBlur` (React Aria `Checkbox` and `Radio` fire them); `<ST_Tooltip standalone open={open} title={checkboxTitle ?? localization...}>` wraps the `RadioGroup` or `ST_Checkbox` as base does at `:172`; the `inline-flex` span goes
- `ST_FilterCheckbox`: the same around the `Label`, events on the `ST_Checkbox`, title `checkboxProps?.title ?? filterLabel` as base `:81`
- `getST_RowExpandColumnDef`: the same around the value span with `onPointerEnter` and `onPointerLeave`, `side="right"` as base `:41`; the `title` attribute stays for the native tooltip
- Does NOT add `tabIndex` or a role to any wrapper; the events live on the control
