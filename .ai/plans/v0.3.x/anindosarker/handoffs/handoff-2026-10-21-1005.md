## Gotchas

- `pnpm release` fails on protected `master`; the two releases were done by hand: branch `release/<v>` from `origin/master`, bump both `package.json` versions, rename `## Unreleased` in `CHANGELOG.md` to `## <v> - <date>` with a fresh `## Unreleased` above, commit `chore: version <v>`, PR into `master`, `gh pr merge --merge`, `git tag v<v> <merge sha>`, push the tag (tags are not covered by the rule).
- `gh pr merge` merged the 0.3.2 bump PR while some checks were still pending; the ruleset requires a PR, not green checks. Wait for checks explicitly before merging.
- `release.yml` smoke under the GitHub runner showed failures not seen locally (example tables with `rows=0` on `/docs/guides/cell-actions` and `/docs/guides/customize-components`, "file copied clip≠shown" on two pages). If the v0.3.2 run is red on those, they are CI timing or network, not content; investigate against production with Playwright before changing checks.
- Usage limits killed agents mid-run twice; coder, fix and gate stages run on opus now. Adding `model` to a workflow script changes its resume cache key.
- After a Claude Code session restart, workflow journals must be copied from the old session's `subagents/workflows/<run>` folder into the new session's before `resumeFromRunId` works.
- `pnpm format` rewrites the installed copies under `apps/shadcn-table-docs/components/ui-*` unless they are in `.prettierignore` (part 05 added them); never commit that churn.
- `next start -p <port>` needs `NEXT_DIST_DIR=.next`, because `next.config.mjs` maps other ports to `.next-<port>`; `next dev -p <port>` adds `.next-<port>` entries to the docs `tsconfig.json`, revert them.
- Reserved ports: 3000, 5173, 5273, 5320, 5404, 5406, 6006, 6007, 6306. Never `pkill`.
- `curl` is hook-blocked in this environment; use `node -e` with fetch inside `ctx_execute`.
