# 05: docs app layout

## 1. Architecture

### 1.1 Overview

The docs app folder was renamed to `apps/docs` without being asked, its two installed library
copies are named `ui` and `ui-base`, and the Base UI code view shows `ui-base` imports that
no user has after install. Decision: [decisions.md](decisions.md) "Docs app" 1 and 2.
Runs after [04](04-package-layout.md) (the installer reads `registry/<base>/`) and
[02](02-docs-weight.md) (shares `example-snippet.tsx`, `code-explorer.tsx`,
`example-variants.mjs`; 02 merges first).

### 1.2 Goals

- App at `apps/shadcn-table-docs`, package name `shadcn-table-docs`, Vercel deploys from the
  new root
- `components/ui-radix/` and `components/ui-base/` hold the installed copies; no
  `components/ui/` in the app
- `examples/<slug>/` sources import `@/components/ui/...` and are what the code view shows on
  both bases; `.radix/` and `.base/` variants are generated and gitignored
- `pnpm lib:install radix` and `pnpm lib:install base` each reinstall one folder with no
  diff when the library is unchanged
- Page checks assert `@/components/ui/` imports in the code view on both bases

### 1.6 Components

#### 1.6.1 Data artifacts

- `vercel.json` `services.docs.root` becomes `apps/shadcn-table-docs`
- `components.json` `aliases.ui` becomes `@/components/ui-radix`
- `apps/shadcn-table-docs/.gitignore` adds `/examples/.radix/`
- `apps/shadcn-table-docs/registry.json`: example items regenerated; only the folder prefix
  changes

#### 1.6.2 Folder rename

`git mv apps/docs apps/shadcn-table-docs`, one commit, then every path reference.

- Updates `vercel.json`, `.prettierignore`, `CONTRIBUTING.md`, `.github/workflows/ci.yml`,
  `scripts/registry/examples.mjs` and `hosted.mjs` output paths, `registry/README.md`, the
  GitHub URL builder in `example-snippet.tsx`, the app's `README.md`
- Does NOT change the package name

**Stays unchanged:** `turbo` filters (by package name), the app's own relative paths.

#### 1.6.3 UI folders

- `git mv components/ui components/ui-radix`; `components.json` `aliases.ui`
- Every app import of `@/components/ui/` outside `examples/` becomes `@/components/ui-radix/`
  (about 30 files: `content/docs`, `components/prop-tables`, `lib/prop-tables`,
  `components/dev-home`, `app/api`); the installed files' own imports are rewritten by the
  CLI on reinstall
- `eslint.config.mjs` ignores, `.prettierignore`, `tsconfig.json` entries follow
- Does NOT touch `components/ui-base/`

#### 1.6.4 Installer

`scripts/install.mjs <base>` replaces `scripts/install-base.mjs` and the `lib:install` npm
script.

- Writes a temporary `components.json` with the base's style (`radix-nova`, `base-nova`) and
  `aliases.ui` `@/components/ui-<base>`
- Runs `shadcn add` for the library item and the locale items from
  `packages/shadcn-table/public/r/`
- Restores `components.json`, `app/global.css`, `package.json` and the lockfile; prints what
  it wrote
- Does NOT install into any other folder

**Operations:**

| Operation           | Status   | Notes                                    |
| ------------------- | -------- | ---------------------------------------- |
| `scripts/install.mjs` | new    | generalised from `install-base.mjs`      |
| `lib:install`       | refactor | takes `<base>`                           |
| `lib:install:base`  | refactor | removed                                  |
| `install-base.mjs`  | refactor | removed                                  |

#### 1.6.5 Example variants

`lib/example-variants.mjs` generates two variants per example from the base-neutral source.

- `.radix/`: `@/components/ui/` to `@/components/ui-radix/` only
- `.base/`: `@/components/ui/` to `@/components/ui-base/` plus the existing `asChild` to
  `render` transform
- Removes stale variant folders; runs on `predev`, `build`, `examples:variants` as today
- Does NOT rewrite anything else

**Interfaces:**

```typescript
// lib/example-variant-dir.mjs
export const VARIANT_DIRS = { radix: '.radix', base: '.base' };
```

**Stays unchanged:** `rewriteAsChild`, the prettier formatting of output, `listExampleFiles`.

#### 1.6.6 Variant consumers

- `components/example-variant.tsx` loads `@/examples/.radix/<name>/TS` and `.base/...`
- `components/dev-home/shared/live-table.tsx`, `dev-home/v12/signal-table.tsx`,
  `dev-home/shared/outline-tiles.tsx` import from `.radix/`
- `lib/example-source.ts` reads the base-neutral source for the code view, one `files` set
  for both bases; `example-snippet.tsx` keeps install command and prompt per base
- `tsconfig.json` includes `examples/*/index.tsx`, `examples/.radix/**`, `examples/.base/**`
  and excludes the other files under `examples/<slug>/`; `next build` compiles only what is
  imported, so sources are never bundled

**Operations:**

| Operation                   | Status   | Notes                                 |
| --------------------------- | -------- | ------------------------------------- |
| `example-variant.tsx` loaders | refactor | two generated dirs                  |
| dev-home imports            | refactor | three files                           |
| `readExampleFiles()`        | refactor | no `base` parameter for sources       |
| `ExampleVariantData.files`  | refactor | shared across bases                   |

#### 1.6.7 Page checks

- `scripts/page-checks/_helpers.mjs` code-view assertion: both bases show
  `@/components/ui/shadcn-table` imports and no `ui-radix` or `ui-base`
- Does NOT change the live example assertions

#### 1.6.8 Registry example items

- `scripts/registry/examples.mjs` reads `examples/<slug>/` sources as today; they already
  ship `@/components/ui/` imports
- Does NOT change item names or file lists

#### 1.6.9 Docs text

- Install page, `CONTRIBUTING.md` docs section and the app `README.md` name the new script
  and folders
