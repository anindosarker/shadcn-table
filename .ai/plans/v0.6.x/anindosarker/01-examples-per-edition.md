# 01: examples per edition

## 1. Architecture

### 1.1 Overview

The 116 docs examples are one Radix-shaped source each. The docs rewrite them per edition
with string transforms (`lib/example-variants.mjs`) for the live demos, but the registry items
`example-<slug>` embed the Radix source in every edition's `/r/<edition>/`, so `shadcn add`
on Base UI or React Aria gets code its parts reject, and the code view shows Radix code on
every edition. Decision 1 in [decisions.md](decisions.md): one complete hand-written set per
edition, guarded for drift like the library trees.

### 1.2 Goals

- `examples/<edition>/<slug>/` exists for every edition in `EDITIONS` and every example; the
  three sets differ only in the files listed in `scripts/registry/examples-<edition>-diff.json`,
  enforced by `pnpm check:bases`
- The live demo, the code view and the registry item of an edition all come from that
  edition's folder; `/r/base/example-react-query.json` contains no `asChild`
- Every edition's example set type-checks against that edition's installed parts in the docs
  `types:check`
- `custom-headless` uses the shadcn `Table` part on radix and base and the React Aria
  `Table` collection on aria
- The prop rewrite is gone; the import rewrite stays

### 1.6 Components

#### 1.6.1 Data artifacts

- `examples/<edition>/<slug>/*`: `git mv examples/<slug>/{TS.tsx,...} examples/radix/<slug>/`,
  copied to `base/` and `aria/`, then the files that fail `types:check` on their edition are
  rewritten by hand in that edition's idiom (today: `advanced`, `custom-top-toolbar`,
  `editing-crud-cell`, `editing-crud-table`, `enable-column-grouping`, `export-to-csv`,
  `export-to-pdf`, `react-query`, `server-side-data/components/UsersTable.tsx`; plus
  `custom-headless` on every edition)
- `examples-base-diff.json`, `examples-aria-diff.json`: paths relative to the edition folder
  (`advanced/TS.tsx`), sorted
- `examples/<slug>/index.tsx` wrappers deleted; `examples/map.tsx` regenerated
- `registry.json` (docs): regenerated, 3 items per example
- `.gitignore`: unchanged (`examples/.radix/` and siblings)
- `CHANGELOG.md` `## Unreleased`: `### Fixed` the registry example items for Base UI and
  React Aria; `### Changed` examples per edition, the code view shows the selected edition's
  source; GitHub-namespace names `example-<slug>-base`, `example-<slug>-aria`
- `CONTRIBUTING.md` (layout tree, examples section, install from a branch, registry items)
  and `docs/code-of-conduct/coding-standards.md` (Layout, Editions, Imports, Gates): the new
  layout, the guard, the rule that a common example change is made in every folder

#### 1.6.2 `scripts/example-map.mjs` and `examples/map.tsx`

- Generates `map.tsx` from `examples/radix/*` slugs (the reference set defines the list):
  one component per slug rendering `ExampleSnippet`, named `<PascalCase(slug)>Example`, the
  same names `map.ts` carries today; exported individually and as `exampleComponents`
- `example-groups/*.tsx` import those names from `@/examples/map`
- `lib/example-pages.mjs` `readExampleExportName` derives the name from the slug with the
  same `pascal` helper, no `index.tsx` read
- Does NOT change `components/mdx.tsx` beyond the import path

#### 1.6.3 `lib/example-variants.mjs`

- For each edition, copies `examples/<edition>/<slug>/*` to `examples/.<edition>/<slug>/*`
  with `rewriteImports` only, prettier kept
- `rewriteAsChild`, `renameAttribute`, `rewriteAriaParts`, `toVariant`'s edition branches deleted
- Header comment rewritten for the new contract

**Stays unchanged:** `lib/example-variant-dir.mjs`, `components/example-variant.tsx`,
`components/dev-home/**` (they import the generated `.radix` folder), `.gitignore`,
tsconfig `include`.

#### 1.6.4 Code view and prompt

- `lib/example-source.ts`: `exampleDir(name, base)`, `readExampleFiles(name, base)`
- `components/mdx/example-snippet.tsx`: `variantFor(base)` reads that base's files; the
  GitHub link moves into `ExampleVariantData` and points at `examples/<base>/<name>`
- `components/example-playground.tsx`: shows the selected variant's files and link (the type
  already carries files per variant)
- `lib/example-prompt.ts`: reads the item `editionItemName(\`example-${name}\`, base)` from
  `registry.json`; the install command and target paths unchanged

#### 1.6.5 Registry items

- `editions.mjs`: `editionItemName(name, edition)`: `name` for `REFERENCE_EDITION`, else
  `${name}-${edition}` (the rule `shadcn-table`, `shadcn-table-base`, `shadcn-table-aria`
  already follows); `build.mjs` and `lib/install.ts` may adopt it, not required here
- `examples.mjs`: for every edition and slug one item, name by `editionItemName`, `files[].path`
  `examples/<edition>/<slug>/<file>`, `target` unchanged (`@components/examples/<slug>/...`),
  `registryDependencies` and `dependencies` from that edition's sources; `--resolve` writes all
- `hosted.mjs`: `public/r/<edition>/` carries that edition's example items renamed to the
  plain `example-<slug>` (same move `HOSTED_NAME` makes for the main item), so
  `lib/install.ts` `exampleAddCommand`, the `@st` namespace and `smoke.mjs` stay as they are
- `install.yml`: the example step adds `example-basic`, `example-basic-base` or
  `example-basic-aria` per scenario (`ITEM`-style expression); `pr.yml` `registry` job dry-runs
  `example-basic-base` and `example-basic-aria` next to `example-basic`
- Does NOT change the hosted item names or the namespace form

#### 1.6.6 `check-bases.mjs`

- Second root pair next to the library: `apps/shadcn-table-docs/examples/<edition>` against
  `examples/radix`, allow list `scripts/registry/examples-<edition>-diff.json`, same rules
  (not listed: byte-identical; listed: present in both; nothing only in one)
- One summary line per pair; `pnpm check:bases` and the CI `bases` job unchanged
- Does NOT copy or edit files

### 1.7 Dependencies and env: none

## 2. Instructions for AI

Tracker `01-tracker.md`. Branch `v0.6/examples-per-edition` from `claude/review`, worktree
`07`. One coder for phases 01 and 03, one or two coders for phase 02 split by edition, one
reviewer, one verifier. Halt on: a wrapper `index.tsx` that is not the one-line
`ExampleSnippet` form (list them, stop), a part edit, an example that cannot be written on
an edition at all.

### 2.1 Phases

#### 2.1.1 Phase 01: layout

- 1.6.1 moves and copies, wrappers deleted, 1.6.2, 1.6.3, 1.6.4
- Gate: docs `types:check`; the base and aria errors are the phase 02 work list, recorded in
  the tracker

#### 2.1.2 Phase 02: edition copies

- Rewrite every listed file by hand in its edition's idiom: Base UI `render` for `asChild`;
  React Aria `isDisabled`, `onChange` on `RadioGroup`, `TooltipTrigger` wrapping trigger and
  `Tooltip`, `onChange` on `Checkbox`; `custom-headless`: shadcn `Table`, `TableHeader`,
  `TableRow`, `TableHead`, `TableBody`, `TableCell` on radix and base, the aria `Table`
  collection parts (`TableHeader`, `Column`, `TableBody`, `Row`, `Cell`) on aria
- Add each rewritten path to the edition's diff list
- Gate: docs `types:check`, `lint`, `pnpm check:bases`, page checks `d` and `e` on every
  edition

#### 2.1.3 Phase 03: registry

- 1.6.5, 1.6.6; `pnpm registry:items && pnpm registry:hosted`; `install.yml`, `pr.yml`

#### 2.1.4 Final phase: docs and gates

- 1.6.1 docs and changelog; delete dead code (the rewrite helpers, `index.tsx` wrappers if
  any remain); 2.2; CI-only PR into `claude/review`

### 2.2 Gates

  `examples/base/basic/TS.tsx` turns it red
- `pnpm --filter shadcn-table-docs types:check && lint && build`: green
- `node apps/shadcn-table-docs/scripts/page-checks/d.mjs` and `e.mjs`: green on radix, base, aria
- `pnpm registry:items && pnpm registry:hosted`: `public/r/base/example-react-query.json` has
  `render=` and no `asChild`; `public/r/aria/example-advanced.json` has `isDisabled`
- `shadcn registry validate` and `shadcn add anindosarker/shadcn-table/example-basic-aria#<sha> --dry-run`: green
- `pr.yml` green on the CI-only PR (15 checks, 5 installs)
