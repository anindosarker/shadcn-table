## 1. Architecture

### 1.1 Overview

Two places in the docs app state or offer something the code does not do. The column filtering guide still says the default filter is fuzzy and does not mention that date, datetime and time columns default to `equals` and compare as dates since spec 40 (D94). The React Query example offers every filter mode on its text columns while its mock route applies a substring match whatever mode is sent (D95). Both are small docs-app edits with no library change, so they share one spec.

### 1.2 Goals

- The guide says date, datetime and time columns default to `equals` and compare by local day, minute or time of day, also for `Date` accessors; no other wording changes (D94).
- On the React Query example the five text columns offer only the contains mode; the route is unchanged (D95).
- The perf budget of the docs E2E stays as it is, 600 ms under `--ci` and 300 ms locally: no change (D48).
- Acceptance: programmatic. `pnpm test docs-e2e --base base` green; `grep -c "columnFilterModeOptions: \['contains'\]" apps/shadcn-table-docs/examples/<base>/react-query/TS.tsx` prints 5 on each base; on a production build on a P6 port, the filter mode menu of First Name on `/docs/examples/react-query` lists one mode (one screenshot per base, paths in the tracker); `git diff origin/claude/review --stat -- apps/shadcn-table-docs/content` lists only `column-filtering.mdx`.
